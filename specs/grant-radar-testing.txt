TESTING THE GRANT RADAR VERIFICATION FLOW — WITHOUT CORRUPTING THE COUNTER

There are two environments needed before testing this feature. If they do not already exist, create them now.

——

STEP 1 — CREATE A TEST ENVIRONMENT

In Railway, create a second deployment of the Bridge app called "Bridge Staging." It connects to a separate Supabase project called "bridge-staging" — not the production database. It uses its own environment variables including its own ANTHROPIC_API_KEY, RESEND_API_KEY, and database URL.

The staging URL will be something like: bridge-staging.up.railway.app

All testing happens at the staging URL against the staging database. The production site at captainsbridge.io is never touched during testing.

If creating a full staging environment is too time-consuming right now, use the minimum viable alternative: add a TEST_MODE environment variable to the existing Railway deployment set to "true." When TEST_MODE is true, grant wins that are approved go into a separate grant_wins_test table instead of grant_wins, and the community counter reads only from grant_wins (not grant_wins_test) so test data never affects the live counter. This is less ideal than a full staging environment but gets the job done safely.

——

STEP 2 — TEST THE EMAIL SYSTEM FIRST

Before testing anything else, confirm Resend is working. Run this test independently:

Create a temporary route: GET /api/test-email
This route sends a simple test email to the ADMIN_EMAIL address using Resend with subject "Bridge email test" and body "If you received this, Resend is working correctly."

Visit that URL in the browser. Confirm the email arrives within 60 seconds. If it does not arrive, check:
- RESEND_API_KEY is present in Railway environment variables
- The sending domain is verified in the Resend dashboard
- The from address uses the verified domain

Do not proceed to testing the grant verification flow until this test email arrives successfully. Delete this test route after confirming it works.

——

STEP 3 — TEST THE FULL VERIFICATION FLOW END TO END

Use a test member account — not the main account. Create a second account at the staging URL or use a throwaway email address on the production site if staging is not set up.

With the test account:

1. Go to Grant Radar. Complete the supplemental intake if needed.
2. Run a scan. Confirm results appear.
3. Click "I applied for this" on any grant result. Enter yesterday's date. Save it.
4. Click "I received this grant." Enter $1,000 as the test amount.
5. Upload a test image — a screenshot, a blank PDF, anything. This is a test so the document does not need to be real.
6. Click "Submit for verification."
7. Confirm the button changes to "Verification pending" status.
8. Check the admin email inbox. Confirm the notification email arrived with the correct grant name, the $1,000 amount, and a working link to view the uploaded document.
9. Click "Approve this win" in the admin email.
10. Confirm the test member account receives a congratulations email.
11. Check the grant_wins table in Supabase. If using TEST_MODE, check grant_wins_test. Confirm one row exists with amount_received = 1000 and verified = true.
12. Check the community counter on the landing page. If using TEST_MODE the counter should NOT change since it only reads from grant_wins not grant_wins_test. If using the staging environment the staging landing page counter should show $1,000.

If all 12 steps pass, the feature is working correctly and safe to use in production.

——

STEP 4 — TEST THE REJECT FLOW

Repeat steps 1 through 7 with a second test submission. This time click "Reject this submission" in the admin email instead of approving it. Confirm:
- The test member receives the rejection email with the resubmission language
- The grant_wins table does NOT have a new row
- The community counter does NOT change

——

STEP 5 — CLEAN UP TEST DATA

After all tests pass, delete the test rows from grant_applications and grant_wins_test (or the staging database) so no test data persists. The production grant_wins table should remain at zero until a real member submits a verified win.

Remove the TEST_MODE environment variable if it was used, or leave the staging environment running for future testing.

——

THE COUNTER STARTS AT ZERO AND THAT IS CORRECT

The live counter on captainsbridge.io will show $0 until the first real verified grant win is submitted and approved. This is intentional and honest. Do not seed the counter with fake data. The first real win will move it and that moment is worth waiting for.
